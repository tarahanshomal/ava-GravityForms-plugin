# پیامک آوا برای Gravity Forms

افزونهٔ مستقل **ava-GravityForms-plugin** برای اتصال فرم‌های Gravity Forms به [پنل آوا](https://ava.tarpardaz.com)، توسعه‌یافته توسط [طراحان شمال](https://github.com/tarahanshomal).

- اعلان پیامکی پس از ثبت فرم، با feed جداگانه برای هر کاربرد.
- انتخاب فیلد شمارهٔ همراه کاربر یا حداکثر پنج شمارهٔ ثابت مدیر.
- متن قابل ویرایش با merge tagهای Gravity Forms و شرط ارسال هر feed.
- تنظیمات فارسی، پشتیبانی از شماره‌های ایران و ارقام فارسی و عربی.
- ثبت نتیجهٔ درخواست برای هر ورودی، تازه‌سازی گزارش آوا و جلوگیری از ارسال تکراری خودکار همان feed.

## نصب و راه‌اندازی

نیازمندی‌ها: PHP **7.4+**، وردپرس **6.5+** و Gravity Forms **2.8+**. Gravity Forms تجاری است و باید جداگانه نصب و فعال شود؛ این بسته شامل آن نیست.

1. فایل **ava-GravityForms-plugin-1.0.0.zip** را از [انتشارها](https://github.com/tarahanshomal/ava-GravityForms-plugin/releases) بگیرید. ZIP پیوست انتشار قابل نصب است؛ فایل خودکار «Source code» بستهٔ نصب نیست.
2. در **افزونه‌ها ← افزودن افزونه ← بارگذاری افزونه** ZIP را نصب و فعال کنید.
3. در پنل آوا یک کلید API با دسترسی‌های **`sms:send`** و **`sms:read`** بسازید.
4. در **تنظیمات ← Ava Gravity Forms** نشانی HTTPS پنل و کلید را وارد و اتصال را فعال کنید. اتصال پس از نصب خاموش است. نشانی پیش‌فرض **`https://ava.tarpardaz.com`** است؛ پنل اختصاصی باید متعلق به همان حساب API باشد.
5. در تنظیمات فرم Gravity Forms بخش **Ava SMS** را باز کنید و یک feed بسازید. نام feed، گیرنده و متن را وارد کنید؛ در صورت نیاز شرط ارسال را فعال کنید.
6. ثبت فرم و نتیجهٔ feed را در محیط آزمایشی خود بررسی کنید. درخواست واقعی می‌تواند پس از تأیید و شروع در آوا هزینه ایجاد کند.

شمارهٔ فرستنده را فقط اگر برای حساب فعال است وارد کنید؛ خالی گذاشتن آن انتخاب خط را به آوا می‌سپارد. دسترسی تنظیمات اتصال به مدیر دارای `manage_options` محدود است. مدیریت feedها نیز به مدیر دارای `manage_options` محدود است.

## گیرنده و متن

هر feed یکی از دو حالت دارد: شماره از فیلد فرم، یا حداکثر **پنج شمارهٔ ثابت**. برای اعلان به کاربر، فیلد شمارهٔ همراه را انتخاب کنید. اگر از فیلد Phone استفاده می‌کنید، قالب آن را در Gravity Forms روی International بگذارید؛ فیلد Text تک‌خطی نیز پشتیبانی می‌شود. برای مدیران، شماره‌های ثابت را در تنظیم feed وارد کنید. برای ارسال به هر دو گروه، دو feed جداگانه بسازید.

شماره‌ها باید همراه ایران باشند؛ قالب‌های `09123456789`، `+989123456789` و `00989123456789` پذیرفته و به قالب محلی تبدیل می‌شوند. ارقام فارسی و عربی نیز قابل استفاده‌اند. شمارهٔ ثابت یا خارجی پشتیبانی نمی‌شود.

متن feed از merge tagهای معمول Gravity Forms پشتیبانی می‌کند. برای درج یک فیلد از انتخابگر merge tag استفاده کنید؛ نمونهٔ زیر فرض می‌کند شناسهٔ فیلد نام ۱ است:

```text
{نام:1} عزیز، فرم شما در {form_title} ثبت شد.
شماره پیگیری: {entry_id}
```

فقط اطلاعات لازم را در پیام بگذارید. متن نهایی پس از جای‌گذاری باید بین ۱ تا ۱۰۰۰ نویسه باشد. متن طولانی ممکن است چند بخش پیامک شود؛ تعرفه و پذیرش نهایی را آوا تعیین می‌کند. شرط feed با منطق بومی Gravity Forms ارزیابی می‌شود. این افزونه برای **اعلان متنی** است و احراز هویت شماره، تولید یا بررسی OTP ندارد.

## پذیرش، بررسی و تحویل

API فعلی آوا درخواست پیامک تکی را در صف مشترک **بررسی محتوا** ثبت می‌کند. پاسخ **۲۰۲** فقط پذیرش درخواست برای بررسی است. مالک پنل باید درخواست را تأیید کند و سپس ارسال را صریحاً آغاز کند؛ تأیید به‌تنهایی ارسال را شروع نمی‌کند. اگر feed ثبت شده ولی پیام نرسیده است، وضعیت بررسی و آغاز کمپین مربوط را در آوا ببینید.

ثبت feed، پذیرش درخواست، تأیید محتوا، پذیرش اپراتور و تحویل، مراحل متفاوت‌اند. وضعیت `delivered` نیز گزارش سرویس‌دهنده است و خواندن پیام توسط مخاطب را اثبات نمی‌کند. افزونه اطلاعات بررسی بازگشتی آوا را همراه نتیجه نگه می‌دارد. در صفحهٔ جزئیات ورودی، بخش آوا خلاصهٔ گیرندگان پوشیده و وضعیت درخواست را نشان می‌دهد. مدیر می‌تواند گزارش را با درخواست خواندن `GET /api/v1/sms/{id}` تازه کند؛ این کار پیام تازه نمی‌فرستد. گزارش پنل آوا مرجع وضعیت نهایی است.

برای هر ورودی و feed، پیش از تماس شبکه یک نشانگر پایدار و اتمی ثبت می‌شود تا اجرای تکراری باعث ارسال دوباره نشود. درخواست‌ها شناسهٔ idempotency دارند. در خطای ارتباطی یا نتیجهٔ نامشخص، افزونه **خودکار دوباره ارسال نمی‌کند**. اجرای مجدد همان feed روی همان ورودی نیز پیام را تکرار نمی‌کند؛ نتیجهٔ قبلی و گزارش آوا را بررسی کنید. این محافظ ممکن است پس از قطع ناگهانی پردازش، درخواست را نامشخص نگه دارد تا از ارسال و هزینهٔ تکراری جلوگیری شود.

## نگهداری کلید

کلید ذخیره‌شده در فرم تنظیمات بازنمایی نمی‌شود. ورودی خالی کلید قبلی را حفظ می‌کند؛ حذف کلید باید صریح باشد. می‌توانید به‌جای ذخیره در تنظیمات، پیش از خط پایان تنظیمات `wp-config.php` تعریف کنید:

```php
define( 'AVA_GF_API_KEY', 'YOUR_AVA_API_KEY' );
```

مقدار نمونه را با کلید خود جایگزین کنید. وقتی این ثابت تعریف شده باشد، افزونه از آن استفاده می‌کند و مقدار ثابت را در تنظیمات پایگاه داده کپی نمی‌کند. کلید را در Git، گزارش خطا، تیکت یا تصویر منتشر نکنید. اگر کلید افشا شد، در آوا آن را لغو و جایگزین کنید.

## حریم خصوصی و سرویس بیرونی

هنگام اجرای feed، افزونه شمارهٔ گیرنده، متن جای‌گذاری‌شده، فرستندهٔ اختیاری و کلید احراز هویت را با HTTPS به پنل آوای تنظیم‌شده ارسال می‌کند؛ endpoint ارسال `POST /api/v1/sms` است. اگر متن حاوی فیلدهای فرم باشد، همان داده‌ها به آوا منتقل می‌شوند. برای شرایط سرویس و اطلاعات حریم خصوصی به [پنل آوا](https://ava.tarpardaz.com) مراجعه کنید.

تنظیمات اتصال و شماره‌های ثابت در پایگاه دادهٔ وردپرس نگهداری می‌شوند. نتیجهٔ feed در گزینه‌های مستقل وردپرس با پیشوند `ava_gf_delivery_` و بدون بارگذاری خودکار نگهداری می‌شود و تا حذف ورودی یا حذف کامل افزونه باقی می‌ماند. این سابقه متن پیام، شمارهٔ کامل یا کلید API را ذخیره نمی‌کند؛ نشانگر ارسال تکراری و خلاصهٔ شمارهٔ پوشیده و وضعیت درخواست را نگه می‌دارد. داده‌های فرم و شماره‌های اصلی نیز طبق تنظیمات Gravity Forms در پایگاه داده و پشتیبان‌ها باقی می‌مانند. نمایش شماره در خلاصهٔ افزونه پوشیده است؛ این پوشش، دادهٔ اصلی فرم یا پایگاه داده را حذف نمی‌کند. دسترسی پایگاه داده، بکاپ‌ها و سیاست نگهداری و حذف ورودی‌ها را مطابق نیاز سایت مدیریت کنید. افزونه پاسخ خام API، کلید یا متن پیام را در گزارش نتیجه منتشر نمی‌کند.

## آزمون و ساخت بسته

```sh
php tests/run.php
python3 -m unittest discover -s tests -p 'test_*.py' -v
python3 scripts/package.py
```

آزمون‌های رفتاری از دادهٔ نمونه، قرارداد شبیه‌سازی‌شدهٔ Gravity Forms و HTTP مصنوعی استفاده می‌کنند؛ پیامک واقعی نمی‌فرستند. بررسی یکپارچه در وردپرس موقت نیز از قرارداد شبیه‌سازی‌شدهٔ Gravity Forms استفاده می‌کند. نصب تجاری Gravity Forms در محیط آزمون موجود نیست؛ این بررسی‌ها سازگاری با یک نسخهٔ تجاری خاص یا مسیر کامل مرورگر را اثبات نمی‌کنند. پیش از استفاده برای کاربران، نسخهٔ Gravity Forms و قالب و افزونه‌های سایت خود را در staging بررسی کنید.

CI بررسی نحو و رفتار PHP را روی **7.4، 8.2، 8.4 و 8.5** و آزمون‌های بسته‌بندی را اجرا می‌کند. بسته با فهرست مجاز فایل‌های تولیدی و timestamp ثابت ساخته می‌شود؛ ساخت از محتوای یکسان ZIP یکسان تولید می‌کند. پوشهٔ `build/` شامل ZIP نصب‌شدنی و فایل SHA256 است. تست‌ها، سورس خصوصی پنل، کلیدها و اطلاعات مشتری در بسته قرار نمی‌گیرند.

برای انتشار، نسخهٔ هدر افزونه، ثابت نسخه، `Stable tag` و changelog را هماهنگ کنید. ارسال تگ `vX.Y.Z` گردش انتشار را اجرا می‌کند و پس از گذر بررسی‌ها، ZIP و checksum را در GitHub Releases می‌گذارد. افزونه به‌روزرسان خودکار اختصاصی یا انتشار خودکار WordPress.org ندارد.

## English

Ava SMS notifications for Gravity Forms by Tarahan Shomal. Create native per-form feeds with an Iranian mobile field or up to five fixed administrator recipients, message merge tags and conditional logic. Install Gravity Forms separately, configure **Settings → Ava Gravity Forms** with your Ava HTTPS panel and a key scoped to `sms:send` / `sms:read`, then enable the connection. Persian is the primary interface language.

Ava's current SMS endpoint submits requests for moderation. HTTP 202 does not mean sent or delivered: owner approval and an explicit start in Ava are required. Atomic per-entry/feed guards prevent duplicate sends, and uncertain requests are never automatically retried. This plugin does not implement OTP. Tests use mocked HTTP and simulated Gravity Forms contracts; validate your licensed Gravity Forms version in staging.
